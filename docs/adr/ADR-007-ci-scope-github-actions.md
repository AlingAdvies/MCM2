# ADR-007 — CI-platform en eerste CI-scope: GitHub Actions met format/lint/typecheck

- Status: Accepted, geïmplementeerd
- Datum: 2026-07-27
- Context: MCM2-CLAUDE.md §10 schrijft een OTAP-route voor met GitHub Actions als testomgeving, maar er bestond nog geen `.github/workflows/`. Twee vragen moesten worden beantwoord: (1) welk CI-platform, met het oog op de toekomstige AWS-productieomgeving; (2) welke checks de eerste workflow mag bevatten, gegeven dat Prisma 7 een bevestigd, reproduceerbaar conflict heeft tussen Jest, de Prisma Client Engine/generator-output en de gecompileerde Docker-productiebuild (zie `docs/architecture-review/2026-07-24/04-orm-decision-record.md`), en dat de Prisma 6/Drizzle-spike nog niet is uitgevoerd.
- Besluit, deel 1 — platform: GitHub Actions, ook na de latere AWS-integratie. CI (format/lint/typecheck/test/build) hoeft niet op AWS te draaien; dat is werk vóórdat er een deploy-target bestaat. Zodra er een AWS-acceptatieomgeving komt, wordt dezelfde workflow uitgebreid met een deploy-job die via OIDC-federatie (geen langlevende AWS-sleutels als GitHub Secret) naar ECR/ECS pusht. Geen aparte CI-tool nodig bij de AWS-overgang.
- Besluit, deel 2 — scope van de eerste workflow (`.github/workflows/ci.yml`): uitsluitend `format:check`, `lint:check` en `typecheck`, plus `npx prisma generate` als voorbereidende stap (nodig voor de gegenereerde Prisma-types; dit is niet dezelfde stap als de geblokkeerde Jest/Docker-combinatie). Jest-tests, `docker build` en migratietests tegen een lege database worden pas aan deze workflow toegevoegd zodra de Prisma 6/Drizzle-spike is uitgevoerd en de uitkomst in `04-orm-decision-record.md` is vastgelegd. Tot die tijd zou een workflow met test/build erin permanent rood staan om een reden die al bekend en geaccepteerd is — dat ondermijnt het signaal "rode CI = nieuw probleem".
- Alternatieven:
  - AWS CodePipeline/CodeBuild in plaats van GitHub Actions (verworpen — geen aantoonbaar voordeel voor een solo-eigenaar die dit vanuit GitHub/VS Code wil kunnen volgen; introduceert AWS-specifieke kennis zonder concrete noodzaak nu).
  - Nu al test/build/Docker-build in CI opnemen en bewust rood laten staan (verworpen — het probleem is al erkend en beleidsmatig vastgelegd als blokkade vóór de spike; een permanent rode check voegt niets toe en vertroebelt toekomstige, wél betekenisvolle rode checks).
  - Wachten met elke CI-workflow tot na de P0/P1-fase (verworpen — format/lint/typecheck zijn nu al betrouwbaar groen te krijgen en onafhankelijk van de Prisma-kwestie; uitstellen levert geen voordeel op en laat de repository langer zonder enige geautomatiseerde kwaliteitspoort).
- Gevolgen:
  - Elke PR naar `main` en elke push naar `main` draait format/lint/typecheck; falen blokkeert (nog) niet automatisch de merge zolang er geen branch-protection-regel is ingesteld — dat is een aparte, nog te nemen stap.
  - Bestaande code is bij de invoering van deze workflow opgeschoond (prettier `--write`, en gerichte fixes voor `@typescript-eslint/no-floating-promises` in `src/main.ts` en `@typescript-eslint/no-unsafe-member-access`/`no-unsafe-argument` in `test/health.e2e-spec.ts`) zodat de workflow bij invoering groen start.
  - `lint`-script blijft `--fix` gebruiken voor lokaal gebruik; een apart `lint:check`-script (`--max-warnings=0`, geen autofix) is toegevoegd specifiek voor CI.
  - `.nvmrc` (Node 24) toegevoegd — sluit het openstaande controlepunt uit ADR-005 (geen expliciete, herbruikbare Node-versiebron tussen lokaal en CI) voor het CI-gedeelte; `engines`-veld in `package.json` blijft nog open.
- Openstaand controlepunt: Jest-tests, Docker-build en migratietest tegen een lege database ontbreken nog in CI — expliciet uitgesteld tot na de Prisma 6/Drizzle-spike (zie ADR-004-orm-decision-record en `docs/STATUS.md`). Branch-protection op `main` (verplicht groene check vóór merge) is nog niet ingesteld.
- Reviewmoment: bij afronding van de Prisma 6/Drizzle-spike (workflow uitbreiden met test/build/migratie), en bij het opzetten van de eerste AWS-acceptatieomgeving (workflow uitbreiden met deploy-job).
- Bronnen: `MCM2-CLAUDE.md` §10–§11; `docs/architecture-review/2026-07-24/04-orm-decision-record.md`; `docs/architecture-review/2026-07-24/05-otap-and-maintenance-model.md`; ADR-005-nodejs-versie.md.
